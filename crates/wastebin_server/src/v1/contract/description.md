Conventions that hold for every `/v1` operation:

- Request and response bodies are wrapped in the resource name
  (`{"paste": {...}}`, `{"pastes": [...]}`). Response bodies are closed: a
  field not listed here is a contract violation.
- Every response carries `X-Request-Id` and `Cache-Control: no-store`.
- Every error, including the framework's own rejections, uses the `Error`
  schema. A missing or expired paste is always 404.
- 401 means no or invalid credentials; 403 means valid credentials that do not
  own the resource, or a cookie request without a matching `Origin`.
- Each operation carries `x-phase`: the phase that implements it (P1, P2, P2b).

Credential selection, the same on every operation:

1. A request with an `Authorization` header is judged by that header alone.
   The cookie is ignored, and the two never add up to more authority.
2. A Bearer token that fails verification is 401. The server never falls back
   to the cookie or to an anonymous request.
3. Without `Authorization`, the `uid` cookie decides. A cookie whose signature
   fails counts as absent, as in upstream's signed cookie jar.
4. A request that carries the cookie and writes (creates, edits, deletes,
   consumes a burn-after-reading paste) must send `Origin` equal to the
   configured public URL; otherwise it is 403 before anything else is checked.
5. Credential and `Origin` failures are answered before any password key
   derivation starts.

The cookie holds several identities. An operation on one resource is allowed
when one of them owns it; a create uses the first. An operation that joins two
resources (a paste and a workspace) requires both to belong to the same
identity, not merely to identities the caller holds.
